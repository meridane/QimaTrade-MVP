After the existing authentication check, the middleware permits `/offers/new` without a Product Master only when the first `created` query value is a canonical UUID v4. Missing, malformed, or invalid-first-duplicate references still follow supplier classification. The exception does not bypass authentication, query the database, establish ownership, or make the UUID an authorization credential.
- **Auth test fixture:** `tests/fixtures/mock-supabase-auth-server.mjs` now implements `GET /auth/v1/user` for the single synthetic access token issued by its existing PKCE test callback; unknown tokens return 401. This enables middleware `getUser()` to be exercised by a browser test without contacting a live Supabase project.
- **Browser coverage:** `tests/e2e/offer-creation-confirmation.spec.ts` now verifies (1) a valid confirmation URL remains protected for an unauthenticated visitor; (2) a synthetic authenticated supplier can render the confirmation and reference without a Product Master; (3) “Create another offer” re-enters `/decision-tree?flow=supplier`; and (4) an authenticated request with a malformed confirmation reference still goes through classification. The test installs its synthetic session cookie for both local host aliases used by the Next.js test server.
